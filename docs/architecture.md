# Architecture

`index.html` loads the browser-ready `dist/app.bundle.js` build. Its source entry point is `src/app.js`, which imports the runtime coordinator in `src/main.js`; configuration, streaming-response cleanup, chat title/memory helpers, storage identifiers, and DOM identifiers are maintained in focused modules under `src/config`, `src/api`, `src/core`, `src/ui`, and `src/utils`.

The browser UI persists chats in IndexedDB and model/ad preferences in localStorage. Users choose Umrani 2.0 (MiniMax M2.7), Umrani 2.1 (DeepSeek V4.1-Flash), or Umrani 2.2 (GLM 5.3-Flash). Requests keep the selected model while falling back across ten Dahl provider accounts, and lightweight health checks refresh model availability every two minutes while the page is visible. Umrani 2.2 is unlocked after four manually completed inline ad breaks. Text and source-code attachments are read in the browser and included as text context; image, PDF and DOCX upload is not exposed. The API helper layer handles cumulative chunks, removes private model-reasoning tags, and prevents repeated rendered blocks. After every two complete chat cycles, the Adsterra Native Banner is inserted inline between chat messages. The composer remains disabled until the user manually clicks Close after its 0.5-second delay. A pending ad survives refresh and is propagated to other tabs. Only a confirmed Native Banner script request error triggers the blocker warning; an empty creative container can mean normal no-fill and no longer causes a false blocker result. No full-screen ad overlay is used. The separate Social Bar placement remains enabled for Adsterra’s notification-style ads. Because this is a static frontend, API keys and client-side enforcement logic remain visible to visitors.
