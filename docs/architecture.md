# Architecture

`index.html` loads `src/app.js` as an ES module. The entry point imports the runtime coordinator in `src/main.js`, while configuration, streaming-response cleanup, chat title/memory helpers, storage identifiers, and DOM identifiers are maintained in focused modules under `src/config`, `src/api`, `src/core`, `src/ui`, and `src/utils`.

The browser UI persists chats in IndexedDB and both the completed-chat counter and pending-ad requirement in localStorage. AI requests are sent directly to three Dahl providers in order. Each provider tries DeepSeek first and GLM 5.3 second before the app moves to the next provider. The API helper layer handles cumulative chunks and prevents repeated rendered blocks. There is no token limit: after every two complete chat cycles (one user message plus one successful AI reply per cycle), an Adsterra Social Bar card is inserted inline between chat messages. The composer remains disabled until the user manually clicks Close after its 0.5-second delay. A pending ad survives refresh and is propagated to other tabs. If the Adsterra script or ad bait is blocked, Close remains unavailable until the blocker is disabled and the page is refreshed. No full-screen ad overlay is used. Social Bar supplies Adsterra’s notification-style ad format. Because this is a static frontend, API keys and client-side enforcement logic remain visible to visitors.
